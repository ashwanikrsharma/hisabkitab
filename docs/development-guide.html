Development Guide

How to set up, run, test, and debug the HisabKitab project locally.

Prerequisites

  • Node.js 20.x
  • npm 10.8.2+
  • Git
  • Supabase account with a project created (or Supabase local dev)

For mobile development:

  • Java JDK 21 (OpenJDK recommended)
  • Android SDK (via Android Studio or standalone)
  • EAS CLI (npm install -g eas-cli)

Initial Setup

1. Clone and Install

git clone <repo-url>
cd hisabkitab
npm install

2. Environment Variables

Copy the example env file and fill in your credentials:

cp .env.example .env

Required variables:

VariableWhere UsedDescription
NEXT_PUBLIC_SUPABASE_URLWeb (client + server)Supabase project URL
NEXT_PUBLIC_SUPABASE_ANON_KEYWeb (client)Supabase anonymous/public key
SUPABASE_SERVICE_ROLE_KEYServer onlySupabase service role key (bypasses RLS)

For mobile, set these as EXPO_PUBLIC_ variants in your environment or in eas.json profiles.

Security: Never commit .env or .env.local files. Only .env.example with placeholder values belongs in git.

3. Database Setup

Run Supabase migrations against your database. Migrations are in src/supabase/migrations/ and should be applied in order.

If using Supabase local development:

npx supabase start
npx supabase db reset  # applies all migrations

Running the Project

Web App (Next.js)

npm run web

This starts the Next.js dev server at http://localhost:3000.

Mobile App (Expo)

npm run mobile

This starts the Expo dev server. Scan the QR code with the Expo Go app, or press a to open in an Android emulator.

All Apps (via Turborepo)

npm run dev

Starts both web and mobile dev servers in parallel.

Testing

Unit & Component Tests (Vitest)

npm run test

Tests are co-located with source files:

expenses.ts      → expenses.test.ts
page.tsx         → page.test.tsx

Key rules:

  • Never mock Supabase — use a real test database or supabase local
  • AI tests use recorded fixtures, not live API calls
  • Always use data-testid attributes for selectors, never CSS classes

E2E Tests (Playwright)

cd apps/web
npx playwright test

Playwright config is at src/web/playwright.config.ts. E2E tests live in src/web/e2e/.

Building for Production

Web

npx turbo build --filter=web

Or deploy directly via Vercel CLI:

vercel          # preview deployment
vercel --prod   # production deployment

Mobile (Android APK)

cd apps/mobile
export JAVA_HOME=/opt/homebrew/Cellar/openjdk@21/21.0.8/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
eas build --platform android --profile preview --local

The APK will be output to the current directory.

Build profiles (defined in src/mobile/eas.json):

  • development — Dev client APK with Metro bundler connection
  • preview — Standalone APK with production API URL baked in
  • production — Release build with local credentials

Debugging

Web App

  • Console errors: Check the terminal running npm run web for server-side errors
  • Network issues: Use browser DevTools Network tab to inspect API calls
  • Auth issues: Check that cookies are being set correctly; verify Supabase session in Application > Cookies
  • API debugging: All API routes log errors via console.error — check the terminal output

Mobile App

  • Expo logs: Visible in the terminal running npm run mobile
  • React Native Debugger: Shake device or press m in terminal for dev menu
  • API connection: Ensure EXPO_PUBLIC_API_URL points to the correct server (localhost for dev, hisabkitab.vercel.app for production)
  • Auth issues: Check Zustand auth store state; verify Bearer token is being sent

Database

  • Supabase Dashboard: Use the SQL editor or table view for direct inspection
  • Supabase MCP: AI agents can query the database directly via the MCP server
  • RLS debugging: Test queries with the anon key to verify RLS policies; use service role only for admin operations

Common Development Tasks

Adding a New API Route

  1. Create src/web/app/api/<route>/route.ts
  2. Follow the mandatory handler pipeline:
import { requireAuth } from '@/lib/auth';
import { NextResponse } from 'next/server';
import { z } from 'zod';
import { createActivity } from '@hisabkitab/services';

const InputSchema = z.object({ /* ... */ });

export async function POST(req: Request) {
  const user = await requireAuth(req);
  const body = await req.json();
  const parsed = InputSchema.safeParse(body);
  if (!parsed.success) {
    return NextResponse.json({ error: parsed.error.flatten() }, { status: 400 });
  }
  // ... use @hisabkitab/services functions
  createActivity({ /* ... */ }).catch(console.error);
  return NextResponse.json({ data: result });
}
  1. Add a co-located test: route.test.ts

Adding a New Database Table

  1. Create a migration: src/supabase/migrations/YYYYMMDDHHMMSS_description.sql
  2. Include: CREATE TABLE, ENABLE ROW LEVEL SECURITY, RLS policies, indexes
  3. Add types to src/services/src/types.ts
  4. Add query functions to src/services/src/queries/<domain>.ts
  5. Update barrel exports in src/services/src/index.ts

Adding a New Web Page

  1. Create src/web/app/<route>/page.tsx
  2. Use Server Components by default
  3. Fetch data via API routes (not @hisabkitab/services directly)
  4. Use the existing Tailwind design tokens for styling
  5. Add 'use client' only for interactive components, pushed as far down the tree as possible
