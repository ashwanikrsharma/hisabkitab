Database Guide

Schema, migrations, RLS policies, query patterns, and the @hisabkitab/services package.

Overview

HisabKitab uses Supabase (managed PostgreSQL) with Row-Level Security (RLS) enforced on every table. All database access goes through the @hisabkitab/services package — raw Supabase queries in apps/ are forbidden.

Schema

Core Tables

users
├── id (UUID, PK — matches Supabase auth.users.id)
├── email

├── is_deleted (soft delete)
├── created_at

├── expense_id (FK → expenses)

├── id (UUID, PK)

Migration Rules

  • File naming: YYYYMMDDHHMMSS_description.sql
  • Never modify an existing migration — always create a new one
  • Every new table must include:
ALTER TABLE table_name ENABLE ROW LEVEL SECURITY;
-- RLS policies for SELECT, INSERT, UPDATE, DELETE
-- Indexes on all foreign key columns
-- created_at and updated_at columns

Client Factories (src/services/src/client.ts)

Key Implementation Details

Equal Split Calculation (createExpense)

  • Uses paise-level precision (integer math) to avoid floating-point errors
  • Distributes the remainder penny-by-penny to early members
  • Example: ₹100 split 3 ways = ₹33.34 + ₹33.33 + ₹33.33

Debt Simplification (simplifyDebts)

  • Greedy algorithm: separates members into creditors (positive balance) and debtors (negative balance)
  • Sorts both by absolute balance descending
  • Matches largest creditor with largest debtor, transferring the minimum of both balances
  • Minimizes total number of transactions

Adding New Functions

  1. Create or edit the appropriate file in src/services/src/queries/
  2. Use getServerClient() for the Supabase client
  3. Add explicit TypeScript types for parameters and return values
  4. Throw descriptive errors: new Error('Failed to <action>: <detail>')
  5. Update barrel exports in src/services/src/index.ts

Row-Level Security (RLS)

RLS is enabled on every table. Key policies:

  • Users: Can only read/update their own profile
  • Groups: Can read groups they belong to
  • Group members: Can read members of groups they belong to
  • Expenses: Can read expenses in their groups or direct expenses involving them
  • Settlements: Same as expenses
  • Activity: Can read activity for their groups or direct activity involving them

Testing RLS

Important: Always test with the anon key (not service role) to verify policies work correctly. The service role bypasses RLS entirely and should only be used in server-side code that needs admin access.

Types

Database types are defined in src/services/src/types.ts:

type SplitType = 'equal' | 'exact' | 'percentage';
type SettlementStatus = 'pending' | 'confirmed' | 'disputed';
type AgentName = 'expense-parser' | 'chat-assistant' | 'reminder';

Client-safe types (camelCase) are in src/shared/src/types/index.ts — these mirror the DB types but use JavaScript conventions and omit DB-specific nullable fields.
