05 Development Conventions

API Route Pattern

Every route handler follows this exact order:

import { requireAuth } from '@/lib/auth';
import { CreateExpenseSchema } from '@hisabkitab/shared';
import { createExpense, createActivity } from '@hisabkitab/services';

export async function POST(req: Request) {
  // 1. Auth (first line, always)
  const user = await requireAuth(req);

  // 2. Zod validation
  const body = await req.json();
  const parsed = CreateExpenseSchema.safeParse(body);
  if (!parsed.success) {
    return Response.json({ error: parsed.error.flatten() }, { status: 400 });
  }

  // 3. DB call via @hisabkitab/services
  try {
    const expense = await createExpense(parsed.data);

    // 4. Activity log (non-blocking)
    createActivity({ ... }).catch(console.error);

    return Response.json(expense, { status: 201 });
  } catch (error) {
    // 5. Sanitized errors
    console.error('Failed to create expense:', error);
    return Response.json({ error: 'Failed to create expense' }, { status: 500 });
  }
}

Table Standards

Every table must have: UUID PK via gen_random_uuid(), created_at / updated_at timestamps, RLS enabled, FK indexes, and descriptive RLS policy names.
Migration File Template 
-- YYYYMMDDHHMMSS_description.sql

-- 1. Create the table
CREATE TABLE table_name (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES auth.users(id) NOT NULL,
  -- columns...
  created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT NOW() NOT NULL
);

-- 2. MANDATORY: Enable RLS
ALTER TABLE table_name ENABLE ROW LEVEL SECURITY;

-- 3. MANDATORY: Create RLS policies
CREATE POLICY "Users can view their own data"
  ON table_name FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can insert their own data"
  ON table_name FOR INSERT
  WITH CHECK (auth.uid() = user_id);

-- 4. Indexes on foreign keys
CREATE INDEX idx_table_name_user_id ON table_name(user_id);

Design Principles

Trust through clarity

Financial apps require absolute transparency. Every number, every split, every balance must be immediately clear.

Speed is the feature

Expense logging must be faster than opening a notes app. Optimize for the 3-second expense capture.

Warm, not sterile

Money conversations are sensitive. Use warm colors, friendly language, and gentle animations.

Indian by default

INR formatting (en-IN), UPI integration, Hindi/English mix, Indian phone numbers.

Testing Rules

  • Never mock Supabase in unit tests — use a real test DB or supabase local
  • AI tests use recorded fixtures, not live API calls (avoid cost + flakiness)
  • Co-locate tests next to source files: foo.ts / foo.test.ts

11 Common Pitfalls

These are real issues the team has encountered. Read them before making your first contribution.
critical Never use @vercel/postgres or @vercel/kv

These packages are sunset. HisabKitab uses Supabase for all database access. Always use @hisabkitab/services for queries.

critical Missing requireAuth on API routes

Every protected API route must call requireAuth(req) as its very first line. Forgetting this creates an unauthenticated endpoint. The review-agent checks for this automatically.

critical Raw Supabase queries outside src/services/

Never write supabase.from('table').select() in API routes or components. All database access must go through @hisabkitab/services to ensure consistency, typing, and audit trails.

critical Committing .env.local or credentials

Only .env.example with placeholder values may be committed. Never commit real API keys, tokens, or passwords.

mobile Emoji icons show as ? on iOS simulator

The iOS simulator does not render all emoji reliably. Use Ionicons (from @expo/vector-icons) instead of emoji characters for icons in the mobile app.

mobile EAS Build: hoisted npm packages cause plugin resolution issues

In monorepo setups, npm hoists packages to the root node_modules. This can cause Expo plugins (especially native ones) to fail during EAS builds. Ensure critical native packages are listed in the app's own package.json, not just at the root.

convention Returning raw DB errors to the client

Always return sanitized error messages. Never expose Supabase or Postgres error details to the client — log them server-side with console.error and return a generic message.

convention Not logging AI token usage

Every Claude API call must be tracked in the agent_metrics table using logAgentMetric(). This includes prompt_version, input/output tokens, latency, and success status.
