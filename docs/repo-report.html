1 Project Overview

HisabKitab is an AI-first group expense splitter built for the Indian market. The name comes from Hindi: "Hisab" (calculation) + "Kitab" (book) — your book of accounts.

AI-Powered Live on Vercel India-First

Target Users

Young Indian adults (20s-30s), mobile-first. Designed around Indian currency formatting, UPI-based settlements, and casual Hindi-English communication patterns.

6 Development Conventions

API Route Pattern (Mandatory)

Every API route handler must follow this exact order:

  1. requireAuth(req) — first line of every handler (except webhooks)
  2. Zod validation — validate all inputs with safeParse
  3. @hisabkitab/services — never write raw Supabase queries in API routes
  4. Sanitized errors — never expose raw database or internal errors
  5. Activity logging — log state-changing operations (non-blocking)
  6. console.error only — no console.log in production routes
import { requireAuth } from '@/lib/auth';
import { z } from 'zod';
import { createExpense } from '@hisabkitab/services';

const Schema = z.object({ amount: z.number().positive() });

export async function POST(req: Request) {
  const user = await requireAuth(req);
  const parsed = Schema.safeParse(await req.json());
  if (!parsed.success) return Response.json({ error: parsed.error.flatten() }, { status: 400 });
  const result = await createExpense(parsed.data);
  return Response.json(result);
}
Security Rules
  • RLS enabled on all tables; service_role key is server-only
  • DB queries live exclusively in src/services/
  • Never commit .env.local or any file with real credentials
  • Every Claude API call must include prompt_version + log to agent_metrics

Migration Conventions
  • 6 migrations in src/supabase/ (immutable — never edit existing ones)
  • Format: YYYYMMDDHHMMSS_description.sql
  • Every new table requires: ENABLE ROW LEVEL SECURITY + policies + FK indexes
CREATE TABLE table_name (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  -- columns...
  created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT NOW() NOT NULL
);

ALTER TABLE table_name ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view their own data"
  ON table_name FOR SELECT USING (auth.uid() = user_id);

12 Common Pitfalls

Things That Will Break Your PR

  • Forgetting requireAuth on API routes
  • Writing raw Supabase queries outside src/services/
  • Committing .env.local or credentials
  • Skipping spec-agent — SPEC.md must match reality
  • Deploying with failing tests — regression gates are mandatory
  • Verifying only web — all three platforms must be checked
Platform-Specific Gotchas

EAS Build (Android/iOS)

Hoisted npm packages in the monorepo can cause plugin resolution failures during EAS builds. If an Expo config plugin cannot be resolved, check that the dependency is not hoisted above src/mobile/node_modules/.

iOS Simulator

The iOS Simulator may not render emoji characters correctly. Use Ionicons vector icons instead of emoji for any UI elements.

Supabase RLS

Always test queries with the anon key, not service_role. Missing RLS policies will silently return empty results rather than throwing errors.
