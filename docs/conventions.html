Conventions & Standards

Coding standards, naming rules, file structure, and common pitfalls. The canonical source is CLAUDE.md at the repo root.

TypeScript

  • Strict mode is enabled globally (strict: true, strictNullChecks, noImplicitAny)
  • No any without an explicit justification comment explaining why it's necessary
  • Prefer type over interface for object shapes (use interface only when extending)
  • All async functions must handle errors (try/catch or .catch())
  • Use satisfies operator for type-checking object literals where useful

File Structure

  • One component/function per file for complex logic
  • Co-locate tests next to source: foo.ts → foo.test.ts
  • Use barrel exports (index.ts) at package boundaries only
  • Never write raw Supabase queries in apps/ — import from @hisabkitab/db

API Route Conventions

Every route handler must follow this exact pipeline in order:

1. requireAuth(req) → First line (except webhooks) 2. Zod safeParse on input → Return 400 with error.flatten() on failure 3. Use @hisabkitab/db functions → Never raw Supabase queries 4. Sanitized error responses → Never expose raw DB errors 5. createActivity() non-blocking → Log state changes, catch errors 6. console.error only → No console.log in production

Frontend Conventions

Server Components (Default)

  • All components are Server Components unless they need interactivity
  • Push 'use client' as far down the component tree as possible
  • Every client mutation must call router.refresh() to sync server state

Styling

  • Use the existing Tailwind design tokens (see apps/web/tailwind.config.js)
  • Custom classes: btn-primary, btn-secondary, card, shadow-warm, glass-header
  • Currency display: Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' })

Component Pattern

// Client component with router refresh after mutation
'use client';

export function DeleteButton({ id }: { id: string }) {
  const router = useRouter();

  async function handleDelete() {
    await fetch(`/api/expenses/${id}`, { method: 'DELETE' });
    router.refresh(); // re-fetch server data
  }

  return <button onClick={handleDelete}>Delete</button>;
}

Database Conventions

Migrations

  • Format: YYYYMMDDHHMMSS_description.sql
  • Never modify existing migrations — always create new ones
  • Every new table needs: RLS enabled, policies, indexes, timestamps

Query Functions

  • One file per domain in packages/db/src/queries/
  • Typed inputs and outputs
  • Descriptive error messages: "Failed to <action>: <detail>"
  • Always update barrel exports after adding new functions

Security Rules

Non-Negotiable Security Rules — these are mandatory on every PR.

  1. Never hardcode secrets in source code — use environment variables
  2. Every API route calls requireAuth(req) as its first line
  3. RLS enabled on every Supabase table
  4. Never use service_role key on the client side
  5. Sanitize user input before passing to Claude API prompts

Defense in Depth

Middleware (session refresh, route protection) → API Route (requireAuth, Zod validation) → @hisabkitab/db (query-level checks) → PostgreSQL RLS (row-level enforcement)

AI / Claude API Rules

These apply when implementing the @hisabkitab/ai package:

  1. Prompt versioning — Every Claude API call must include prompt_version: '<name>-v<major>.<minor>' in metadata
  2. Token logging — Every call logs to agent_metrics via logAgentMetric()
  3. Prompt injection guard — Sanitize user-provided text; use it only in the human turn, never in system prompts

Observability

  • All AI operations tracked via logAgentMetric() in @hisabkitab/db
  • State-changing API operations log to activity_log via createActivity() (non-blocking)
  • console.error for error logging — never console.log in production paths

Common Mistakes to Avoid

  1. Raw Supabase queries in apps/ — Always use @hisabkitab/db functions
  2. Returning raw DB errors — Always return sanitized error messages
  3. Missing AI token logging — Every Claude call must log usage
  4. Skipping Zod validation — Every external input must be validated
  5. console.log in production — Use structured logging (console.error for errors)
  6. Forgetting await — TypeScript strict mode catches most, but stay vigilant
  7. Missing RLS policies — Test with anon key to verify
  8. Not updating barrel exports — After adding functions to packages/db/, update index.ts
  9. Direct HTTP calls between agents — Use function imports within the monorepo, never fetch('http://localhost:...')
  10. Missing router.refresh() — Client mutations must refresh server state

Branching & Deployment

  • Main branch: master
  • No CI/CD pipeline — deployments are manual via CLI
  • Web: vercel (preview) or vercel --prod (production)
  • Mobile: eas build --platform android --local
  • Commits should be descriptive and focused on a single change
  • No formal PR process documented — AI agents deploy directly via the orchestrator pipeline
