Project Overview

What HisabKitab is, how it works, its architecture, and key design decisions.

What is HisabKitab?

HisabKitab is an AI-first group expense splitter built for the Indian market. It helps friends, roommates, and travel groups track shared expenses, calculate who owes whom, and settle debts — with first-class support for INR, UPI, and Indian phone numbers.

The name "HisabKitab" (हिसाब-किताब) is a Hindi expression meaning "accounting" or "keeping track of finances."

Target Users

Young Indian adults (20s–30s) who frequently split bills with friends. The app is mobile-first, designed for quick expense entry on the go, with a web dashboard for detailed management.

Key Features

  • Group expenses — Create groups, add members, split bills (equal, exact, or percentage)
  • Direct expenses — Track one-on-one expenses without creating a group
  • Debt simplification — Greedy algorithm minimizes the number of transactions needed to settle all debts
  • Activity feed — Real-time log of all expense and settlement activity
  • Multi-platform — React Native mobile app + Next.js web app sharing the same API
  • Indian-first — INR as default currency, UPI ID validation, +91 phone formatting

Key Design Decisions

DecisionChoiceRationale
API styleRESTSimple, well-understood; no need for GraphQL complexity at this scale
AuthSupabase AuthIntegrated with DB, supports social/phone login, free tier generous
Monorepo toolTurborepoFaster builds with caching, simpler config than Nx
TestingVitest + PlaywrightVitest for unit/component (fast), Playwright for E2E (reliable)
State (mobile)ZustandMinimal boilerplate, React Native friendly
Data fetching (mobile)TanStack QueryAutomatic caching, refetching, and offline support
Styling (web)Tailwind CSSUtility-first, consistent design tokens, fast iteration
Styling (mobile)NativeWindTailwind-like syntax for React Native
DB accessService role + typed queriesType-safe, centralized, RLS still enforced at Postgres level

Deployment

  • Web: Deployed to Vercel via CLI (vercel for preview, vercel --prod for production). No GitHub Actions — deployments are triggered manually by the web-deploy-agent.
  • Mobile: Android APKs built locally via EAS CLI (eas build --platform android --local). No cloud builds configured.
  • Database: Supabase hosted, schema managed via numbered SQL migrations.

Production URLs

  • Web: https://hisabkitab.vercel.app
  • API: Same domain (/api/* routes)
  • Mobile: Points to the web API via EXPO_PUBLIC_API_URL
