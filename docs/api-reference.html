API Reference

All REST API endpoints, request/response formats, and authentication patterns. Base URL: https://hisabkitab.vercel.app/api/ (prod) or http://localhost:3000/api/ (dev).

Authentication

Every API route (except webhooks) requires authentication via requireAuth(req).

Web (Cookie-Based)

Supabase session cookies are automatically included by the browser. The middleware at src/web/middleware.ts refreshes sessions on every request.

Mobile (Bearer Token)

Send the Supabase access token in the Authorization header:

Authorization: Bearer <supabase_access_token>

The requireAuth function tries cookie auth first, then falls back to Bearer token.

Groups

GET /api/groups

List all groups the authenticated user belongs to.

Response
{ "data": Group[] }
POST /api/groups

Create a new group. The creator is automatically added as an admin member.

Body
{
  "name": "Trip to Goa",
  "description": "Beach vacation expenses",
  "currency": "INR"
}
Response
{ "data": Group }
GET /api/groups/[id]

Get a specific group with members.

Response
{ "data": Group & { members: GroupMember[] } }
PATCH /api/groups/[id]

Update group details.

Body
{ name?, description?, currency? }
DELETE /api/groups/[id]

Archive (soft delete) a group.

Group Members

GET /api/groups/[id]/members

List all members of a group.

Response
{ "data": GroupMember[] }
POST /api/groups/[id]/members

Add a member to a group by user ID.

Body
{ "userId": "string" }

Group Balances

GET /api/groups/[id]/balances

Get the net balance for each member and simplified debts.

Response
{
  "data": {
    "balances": [
      { "userId": "...", "name": "...", "balance": 500.00 }
    ],
    "simplifiedDebts": [
      { "from": "...", "to": "...", "amount": 250.00 }
    ]
  }
}

Expenses

GET /api/expenses

List direct (non-group) expenses for the authenticated user.

Query Params

friendId (optional) — filter to a specific friend

Response
{ "data": Expense[] }
POST /api/expenses

Create an expense (group or direct).

Body
{
  "groupId": "uuid" | null,
  "paidById": "uuid" | "self",
  "amount": 1500.00,
  "description": "Dinner at Toit",
  "category": "food",
  "splitType": "equal",
  "splits": [
    { "userId": "uuid", "amount": 750.00 }
  ],
  "friendId": "uuid"
}

Note: Mobile clients can pass "self" as paidById — the API resolves it to the authenticated user's ID.

Response
{ "data": Expense }
DELETE /api/expenses/[id]

Soft delete an expense.

Friends

GET /api/friends/[userId]

Get direct expenses, settlements, and balance between the authenticated user and a specific friend.

Response
{
  "data": {
    "expenses": [...],
    "settlements": [...],
    "balance": { "amount": 500.00, "direction": "owed_to_you" }
  }
}

Settlements

POST /api/settlements

Create a settlement between two users.

Body
{
  "groupId": "uuid" | null,
  "paidById": "uuid",
  "paidToId": "uuid",
  "amount": 750.00,
  "paymentMethod": "upi" | "cash" | "bank_transfer"
}
PATCH /api/settlements/[id]

Update settlement status (e.g., confirm or dispute).

Body
{ "status": "confirmed" | "disputed" }

Activity

GET /api/activity

Get the activity feed for the authenticated user (across all groups + direct).

Response
{ "data": Activity[] }

Users

GET /api/users

Get the authenticated user's profile.

PATCH /api/users

Update the authenticated user's profile.

Body
{ name?, phone?, avatarUrl? }
GET /api/users/search

Search users by phone number or name.

Query Params

q — search term

Response
{ "data": User[] }

Push Tokens

POST /api/push-tokens

Register or update an Expo push token for the authenticated user.

Body
{
  "token": "ExponentPushToken[...]",
  "platform": "ios" | "android" | "web",
  "deviceId": "string" (optional)
}
Response
{ "pushToken": PushToken }
DELETE /api/push-tokens

Deactivate a push token (e.g., on sign-out).

Body
{ "token": "ExponentPushToken[...]" }

Sync

POST /api/sync/pull

Pull changes from the server since a given timestamp. Used by the mobile sync engine for offline-first data synchronization.

Body
{
  "lastSyncedAt": "2024-01-01T00:00:00Z",
  "tables": ["users", "groups", "group_members", "expenses", "expense_splits", "settlements", "activity_log"]
}
Response
{
  "changes": {
    "users": [...],
    "groups": [...],
    "group_members": [...],
    ...
  },
  "timestamp": "2024-03-30T12:00:00Z"
}
POST /api/sync/push

Push locally queued changes to the server. Returns conflicts if any records were modified server-side since the local change.

Body
{
  "changes": [
    { "operation": "create|update|delete", "table": "string", "recordId": "uuid", "payload": {...} }
  ]
}

Webhooks

POST /api/webhooks/whatsapp

WhatsApp webhook endpoint. No authentication required — verified by WhatsApp's own verification mechanism.

GET /api/webhooks/whatsapp

WhatsApp webhook verification (challenge response).

Error Responses

All errors follow this format:

{
  "error": "Human-readable error message"
}
StatusMeaning
400Validation error (Zod parse failure) — includes error.flatten() details
401Unauthorized — missing or invalid auth
404Resource not found
500Internal server error — details logged server-side, generic message returned

Security: Raw database errors are never exposed to clients. All errors are sanitized before returning.

Handler Pipeline

Every API route follows this exact order:

1. requireAuth(req) → 401 if unauthenticated 2. Parse & validate body → 400 if invalid (Zod safeParse) 3. Authorization check → 403 if not permitted 4. Execute via @hisabkitab/services → Business logic 5. createActivity(...) → Non-blocking activity log 6. Return JSON response → Sanitized data
